# jellyfin-plugins

A [Jellyfin](https://jellyfin.org) plugin repository. Add its URL to a Jellyfin
server and the plugins below show up in the server's plugin catalog, where they
install and update like any other plugin.

**This repo only distributes builds.** It contains the catalog manifest
Jellyfin reads, the built plugin zips (as GitHub releases), and the licenses
those plugins are redistributed under. The source code for these builds is
kept in private repositories and is not published here.

These are personal builds, mostly modified versions of existing open-source
plugins, made for my own servers. They're public only because Jellyfin can't
log in to download a catalog. You're welcome to use them, but they come
without support or warranty, and they aren't affiliated with or endorsed by
the original plugin authors. For an upstream plugin's official version or to
report its bugs, use the upstream repository linked in the table below.

## Add to Jellyfin

Dashboard → Plugins → Repositories (Catalog → ⚙ in Jellyfin 12) → **+**, then:

- **Name:** furyetti
- **URL:** `https://raw.githubusercontent.com/furyetti/jellyfin-plugins/main/manifest.json`

## How this repo works

Each plugin is a folder under `plugins/<slug>/`:

| File | Purpose |
|---|---|
| `plugin.json` | Catalog metadata: `guid` (must equal the plugin's `Id`), name, `targetAbi`, upstream repo, license, summary of changes |
| `versions.json` | Published versions with their md5 checksums; written by the publish script |
| `LICENSE` | The redistributed plugin's license (required) |

`manifest.json` and the table above are generated by `scripts/catalog.py build`;
don't edit them by hand. CI fails if they're out of date.

Each version's zip is a GitHub release tagged `<slug>-<version>`, with the
asset named `<slug>-<version>.zip`.

### Publish a version

From the plugin's source repo, build the zip (plugin DLL at the zip root), then:

```bash
../jellyfin-plugins/scripts/publish.sh <slug> <version> <zip>
```

It creates the release, records the version, regenerates the manifest, pushes,
and checks that the published zip matches the recorded checksum.

### Add a plugin

Create `plugins/<slug>/plugin.json` and `plugins/<slug>/LICENSE`, run
`python3 scripts/catalog.py build`, and commit. Then publish its first version.

## What belongs here

Because this repo is public, only built artifacts, catalog metadata and the
licenses they require go here: never source code from the private
repositories, secrets, or anything personal.
